# 游戏服与支付

登录没有服务端接口。渠道用户号由渠道 SDK 交给游戏，游戏自己决定是否存在本地。

有内购时，客户端可以调用建单。请求里的金额会被忽略，金额以商品表为准。客户端支付回调不能发货。

## 建单

`POST /v1/orders`

```json
{
  "appId": "g_xxx",
  "channelCode": "test",
  "channelUserId": "test_user_001",
  "productId": "gem_6",
  "gameOrderId": "local-1",
  "roleId": "r1"
}
```

游戏服建单时可以附带签名。签名串用 `|` 连接，HMAC-SHA256，十六进制小写：

`appId|gameOrderId|channelCode|channelUserId|productId|roleId|timestamp`

密钥是后台里的 appKey。单机客户端建单可以不带签名。

## 渠道支付通知

渠道服务器调用：

`POST /v1/channels/{channelCode}/pay-notify`

```json
{
  "appId": "g_xxx",
  "orderId": "o_xxx",
  "amountFen": 600,
  "timestamp": "1710000000",
  "sign": "..."
}
```

签名字段：`appId|orderId|amountFen|timestamp`。密钥是该渠道的 channelSecret。金额必须和商品表一致。

验签通过后，如果游戏配置了支付通知地址，发行服务再通知游戏服：

`orderId|gameOrderId|productId|amountFen|channelUserId|timestamp`

密钥是 appKey。游戏服确认发货后返回 `{"ok": true}`。同一发行订单号只处理一次。没有通知地址时，订单停在 `paid`，后台可以查看，游戏不能把客户端回调当成发货。

## 激励

只有网游会接受 `POST /v1/reward-completions`。单机返回 409，不写库。
