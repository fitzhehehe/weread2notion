# 游戏接入

游戏工程不写 Java。Android 宿主在启动时调用一次 `AggregatorBridge.start(activity)`，它读取 `assets/aggregator.json`。Unity 和 Cocos 之后只调桥，并轮询 `poll()`。

单机测试配置见 `samples/offline-aggregator.json`。`serverBaseUrl` 为空时，登录、角色和广告都不访问发行服务器。

## 按钮顺序

1. 初始化。`start` 成功后队列里有 `init_ok`。
2. 登录。回调里的 `channelUserId` 是渠道账号，测试渠道固定为 `test_user_001`。
3. 角色上报三次：`create`、`enter`、`levelUp`。
4. 支付。看 `deliverable`，它永远是 false。`kind` 为 `client_only` 时没有发行订单；为 `awaiting_notify` 时要等渠道通知，不能在这个回调里发货。
5. `loadAd("reward", "reward_main")`，等到 `onLoaded`。
6. `showAd("reward", "reward_main")`，激励看 `onReward`。测试渠道的代码位是 `0`。

## Unity

脚本在 `bridges/unity/AggregatorSample.cs`。`AggregatorBridge.start` 需要 Activity，放在 Android 启动代码里，不要从 C# 猜 Activity。

## Cocos Creator

脚本在 `bridges/cocos/aggregator.ts`。同样由 Android 宿主先 `start(activity)`。脚本调用 `login`、`submitRole`、`pay`、`loadAd`、`showAd` 和 `poll`。

## 广告位

游戏只传聚合广告位 ID，例如 `reward_main`。渠道代码位写在包配置或后台映射里。四种类型：`reward`、`interstitial`、`splash`、`banner`。
