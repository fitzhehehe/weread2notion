## 背景

自家发行要把同一款游戏上到 OPPO、vivo、华为、小米。游戏只接一次。登录账号是渠道的，聚合 SDK 把这一次调用交给当前渠道包里的渠道 SDK。单机不部署发行服务器也可以登录，进度留在手机上。

发行服务器只在要认支付账、改广告位映射时使用。它不保存游戏存档。客户端支付回调不能发货。

## 已定范围

- 游戏工程只提供 Unity 和 Cocos Creator 的调用。产出物是 Android 渠道包。
- 第一批渠道是 OPPO、vivo、华为应用市场、小米游戏联运。
- 广告先做广告位。游戏只持有聚合广告位 ID。
- 不做鸿蒙、iOS、小游戏、买量统计、自研广告竞价、存档同步。

## 现在需要你做的

第一家渠道定为 vivo。联运 SDK 4.9.3.1 已从文档页下载并核对。广告包已在你的下载目录，编译环境读不到 `C:\`。

### 1. 把已经下好的广告包交到工程里

1. 打开资源管理器，进入 `C:\Users\Administrator\Downloads`。
2. 把 `vivo_ad_network_sdk_62741.rar` 复制到这个仓库的 `aggregator\vendor\vivo\`。目录没有就新建。这个目录已被 git 忽略，不要执行 git add。
3. 在这条对话里发一句「广告包已放到 aggregator/vendor/vivo」。也可以把这个 rar 直接拖进对话当附件。
4. 不要把 rar 发到公开网页。

### 2. 把两个 key 分开抄

vivo 登录只用应用的 appId，写在包里的 `vivoUnionAppId`。支付签名只用支付 key，放在发行服务器，不进游戏包。账号校验接口不使用这两个 key。

1. 登录 https://dev.vivo.com.cn/ ，打开包名 `com.xinghan.lywy.vivo` 的游戏。
2. 在参数页找到两行 key，看页面上的原文是「账号 key」还是「支付 key」。
3. 不要把完整密钥再发到对话里。在本机 `aggregator/vendor/vivo/params.txt` 里写成两行：`accountKey=` 和 `payKey=`。刚才发来的那一串如果就是其中某一个，在对应行填写，另一行填另一串。
4. `notifyUrl` 现在是空的。登录不需要它。要认支付账时，再填一个公网地址，格式为 `https://你的域名/v1/channels/vivo/pay-notify`，并在 vivo 后台的支付回调里填同一个地址。

### 3. 准备一台 vivo 手机

打开开发者选项里的 USB 调试。用数据线连到跑这个工程的电脑。这一步先不用操作游戏，等适配器用广告包编译通过后再装包。

## 你交来之后会做的
